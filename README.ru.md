# Stenabot

[![CI](https://github.com/MartyStev/LentaBox/actions/workflows/ci.yml/badge.svg)](https://github.com/MartyStev/LentaBox/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE) ![Python 3.12+](https://img.shields.io/badge/python-3.12%2B-blue.svg)

[English](README.md) · [Русский](README.ru.md)

Userbot для Telegram: читает выбранные вами каналы, отсеивает повторы и публикует каждую новость в целевой чат **один раз** — со ссылкой на оригинал.

Новостные каналы весь день пересказывают друг друга. Stenabot сравнивает каждый новый пост с уже опубликованным (точный текст, репосты, нечёткое сходство текста и сходство эмбеддинга *сюжета*), поэтому одно событие появляется в вашей ленте один раз, сколько бы каналов о нём ни написало.

- **Дедупликация по сюжетам**, а не только по одинаковому тексту: эмбеддинги собираются в кластеры, сюжет публикуется не чаще раза за скользящее окно в 24 часа.
- **Публикация ровно один раз.** Перед отправкой новость резервируется в PostgreSQL, после подтверждения Telegram всё сохраняется одной транзакцией. Если исход отправки неизвестен, бот *не* повторяет её вслепую, а спрашивает вас ([неопределённый исход](#неопределённый-исход-отправки)).
- **Сразу или дайджестом**, плюс **тихие часы**: публиковать сразу либо копить заголовки и присылать сводку раз в N часов; ночью ничего не приходит.
- **Стоп-слова**, **сохранение форматирования** оригинала (жирный, ссылки, цитаты), медиа пересылаются там, где это разрешает Telegram.
- **Управление каналами из чата**: следование за подписками и папками самого аккаунта, при желании — автосинхронизация.
- **Рассчитан на работу без присмотра**: догрузка после простоя, оповещения о застое и тишине, watchdog systemd, блокировка единственного экземпляра, миграции, бэкапы с проверкой восстановления.
- Сообщения владельцу на **русском или английском** (`/lang`).

## Как это работает

```
каналы ──▶ Telethon (ваш аккаунт) ──▶ очистка текста ──▶ проверки ──▶ кластер сюжета ──▶ резерв ──▶ целевой чат
                                                          │                                  └─▶ очередь дайджеста ──▶ дайджест
                                                          └─▶ пропуск с записанной причиной (/why)
```

Проверки по порядку: стоп-слово → слишком старое → реклама → точный повтор → репост уже опубликованного оригинала → нечёткий повтор → слишком короткое → сходство эмбеддинга с недавними кластерами (порог `0.92`, центроид кластера — скользящее среднее). Перед публикацией сюжет *резервируется*, поэтому два канала, написавшие о событии в одну секунду, не опубликуют его дважды.

Каждое решение, включая каждый пропуск, хранится с выдержкой текста, так что пороги можно подбирать по реальным данным: `/stats`, `/stats channels`, `/why <ссылка на пост>`.

## Требования

- Python 3.12 или 3.13
- PostgreSQL (разрабатывалось и проверялось на 18). Пользователю БД нужно право создать схему или уже существующая схема в его владении.
- **Сервер эмбеддингов** с OpenAI-совместимым API: например, llama.cpp (`llama-server --embedding`) с `nomic-embed-text` или любой сервис с `/v1/embeddings`.
- Данные Telegram API (`API_ID`, `API_HASH`) с <https://my.telegram.org> и аккаунт Telegram для userbot.

## Быстрый старт с Docker

Docker Compose поднимает бота, PostgreSQL и локальный сервер эмбеддингов (llama.cpp с `nomic-embed-text`):

```bash
cp .env.example .env              # заполните API_ID, API_HASH, TARGET_CHAT_ID, OWNER_ID, DB_PASSWORD
docker compose run --rm bot       # первый запуск: вход в Telegram (номер и код), затем Ctrl+C
docker compose up -d
docker compose logs -f bot
```

Сессия хранится в томе `session`. Уже есть свой сервер эмбеддингов? Уберите сервис `embeddings` и задайте `EMBEDDINGS_URL`.

## Быстрый старт без Docker

```bash
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.lock
cp .env.example .env          # заполните API_ID, API_HASH, TARGET_CHAT_ID, OWNER_ID, DB_PASSWORD, ...
```

1. Создайте пользователя и базу. Схему и таблицы бот создаст сам при первом запуске:

   ```sql
   CREATE ROLE stenabot LOGIN PASSWORD '...';
   CREATE DATABASE stenabot OWNER stenabot;
   ```

2. Запустите сервер эмбеддингов и укажите его в `EMBEDDINGS_URL`.
3. Один раз войдите **в терминале**: Telethon спросит номер телефона и код:

   ```bash
   .venv/bin/python bot.py
   ```

   Без терминала (systemd, Docker) неавторизованная сессия завершает процесс с кодом `3`, а не зависает.
4. Отправьте боту `/menu` с аккаунта владельца (`OWNER_ID`), затем подключите каналы: `/subs` и `/track`, либо `/add @канал`.

Бот публикует в `TARGET_CHAT_ID` от имени аккаунта userbot, поэтому этот аккаунт должен иметь право писать в чат (в канале — быть администратором). `OWNER_ID` — единственный аккаунт, которого бот слушается и которому пишет оповещения; он может отличаться от аккаунта userbot.

## Настройка

Всё, что зависит от развёртывания, берётся из переменных окружения (или `.env`). Канонические имена — в верхнем регистре; нижний регистр принимается для старых установок.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_ID`, `API_HASH` | — | Данные приложения Telegram |
| `SESSION_NAME` | `stenabot_session` | Файл сессии Telethon (можно путь) |
| `TARGET_CHAT_ID` | — | Куда публиковать новости |
| `OWNER_ID` | — | Единственный аккаунт, которому подчиняется бот |
| `DB_HOST` `DB_PORT` `DB_NAME` `DB_USER` | `localhost` `5432` `stenabot` `stenabot` | PostgreSQL |
| `DB_PASSWORD` | — (обязателен) | |
| `DB_SCHEMA` | `stenabot` | Схема для всех таблиц |
| `EMBEDDINGS_URL` | `http://localhost:8081/v1/embeddings` | OpenAI-совместимый адрес эмбеддингов |
| `EMBEDDINGS_MODEL` | `nomic-embed-text` | |
| `LANGUAGE` | `en` | `en` или `ru`; на лету меняется командой `/lang` |
| `DELIVERY_MODE` | `instant` | `instant` или `digest` |
| `DIGEST_HOURS` | `3` | Период дайджеста, 1–24 |
| `QUIET_HOURS` | пусто | например `23:00-08:00` |
| `TIMEZONE` | `UTC` | Часовой пояс (IANA) для тихих часов |
| `LOG_FORMAT` / `LOG_LEVEL` | `text` / `INFO` | `json` — для сборщиков логов |

Настройки доставки, язык и пороги можно менять из чата: они хранятся в базе и переживают перезапуск. Интервалы, окна и лимиты лежат в [`config.py`](config.py) с комментариями.

> **Если вы обновляетесь со старой версии:** язык по умолчанию теперь английский. Чтобы сохранить русские сообщения, задайте `LANGUAGE=ru` или выполните `/lang ru`. Имена переменных в нижнем регистре (`target_chat_id`, `owner_id`, …) по-прежнему работают. Пароль БД больше не имеет значения по умолчанию: задайте `DB_PASSWORD`.

## Команды

Все команды работают только от `OWNER_ID`. Бот работает от имени обычного аккаунта, поэтому вместо кнопок используются номера из последнего списка.

| Команда | Что делает |
|---|---|
| `/menu` | Все команды |
| `/subs [new\|tracked\|текст\|folder Имя] [page N]` | Подписки аккаунта (✅ отслеживается, ⬜ нет) |
| `/track 1 3 5-9`, `/track all`, `/track folder Имя` | Начать отслеживание; `/untrack …` — прекратить |
| `/folders`, `/sync [apply]`, `/autosync [on\|off]` | Папки; сверить подписки с отслеживаемыми; следовать за подписками автоматически |
| `/list`, `/add <ссылка>`, `/remove <ссылка>` | Отслеживаемые каналы (с числом постов за 24 ч); добавить или удалить по `@имени` / ссылке `t.me` |
| `/mode [instant\|digest]`, `/digest [часы\|now]` | Сразу или дайджестом; период дайджеста; отправить его сейчас |
| `/quiet [ЧЧ:ММ-ЧЧ:ММ\|off]`, `/tz [Зона/Город]` | Тихие часы и их часовой пояс |
| `/mute [слово]`, `/unmute <слово>` | Стоп-слова (подстрока без учёта регистра) |
| `/lang [ru\|en]` | Язык сообщений бота |
| `/stats [channels]`, `/why <id\|ссылка>` | Решения за 24 ч; почему пост опубликован или пропущен |
| `/threshold [cluster\|fuzzy значение\|reset]` | Пороги дедупликации без перезапуска |
| `/pending [id\|page N]`, `/pending resolve <id> sent\|failed` | Отправки с неопределённым исходом |

Автосинхронизация удаляет только каналы, подключённые из подписок (`source = 'sync'`). Добавленные через `/add` она не трогает, а отключённые через `/untrack` или `/remove` не возвращает (вернуть можно через `/track`).

## Доставка: сразу, дайджест, тихие часы

- **instant** (по умолчанию): новый сюжет публикуется сразу после проверок — с исходным форматированием и медиа.
- **digest**: сюжеты копятся и уходят одним сообщением из заголовков со ссылками раз в `DIGEST_HOURS`. `/digest now` отправляет очередь немедленно.
- **тихие часы**: в этом окне ничего не публикуется сразу; сюжеты ждут в той же очереди и уходят дайджестом, когда окно заканчивается.

Сюжет в очереди считается опубликованным для дедупликации с момента постановки (пост, резерв и запись очереди пишутся одной транзакцией), поэтому повторно он не выйдет. Дайджест помечается отправленным только после того, как в чат дошли все его части; если часть не ушла, повторяется весь дайджест: повторённый заголовок лучше потерянного.

## Надёжность

- Сообщение, которое не удалось обработать `MAX_PROCESS_ATTEMPTS` раз за время не меньше `GIVEUP_MIN_AGE_SEC`, пропускается (`error_giveup`), чтобы не блокировать канал.
- Отправки идут не чаще одной в `SEND_MIN_INTERVAL_SEC`, чтобы разбор очереди не превращался в поток; сообщения старше `BACKFILL_MAX_AGE_HOURS` после долгого простоя пропускаются.
- Раз в `STALL_CHECK_SEC` бот сверяет курсоры с каналами; о застрявшем канале и о долгой тишине (`SILENCE_ALERT_HOURS`) владелец получает оповещение. Одинаковые оповещения ограничены по частоте.
- Один экземпляр на базу (advisory lock); при потере блокировки процесс завершается. Запросы к БД идут через пул; запросы эмбеддингов повторяются.
- Миграции из `db/migrations` применяются при старте и проверяются по контрольной сумме. **Применённую миграцию менять нельзя — добавляйте следующий номер.**

### Неопределённый исход отправки

Перед отправкой бот резервирует новость в `publication_claims`. После подтверждения Telegram пост, отметка кластера и состояние резерва сохраняются одной транзакцией. Если соединение оборвалось после отправки или БД отказала, резерв остаётся `pending`: автоматический повтор мог бы создать дубль. Бот сообщит вам; сверьте целевой чат и закройте резерв:

- `/pending resolve <id> sent` — пост в чате есть; повторно он не уйдёт.
- `/pending resolve <id> failed` — поста нет; следующий проход отправит его.

Резерв старше `CLAIM_EXPIRE_HOURS` (24 ч) закрывается автоматически как `expired` с уведомлением: новость устарела, канал идёт дальше.

См. [`deploy/README.md`](deploy/README.md): защищённый systemd-юнит (watchdog, `NoNewPrivileges`, файловая система только для чтения), оповещения о падении, ежедневные бэкапы PostgreSQL с внешней копией и ежемесячная проверка восстановления.

## Разработка

```bash
python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements-dev.lock
.venv/bin/python -m pytest -q                      # модульные тесты, без сети и БД
TEST_DB_DSN=postgresql://user@localhost:5432/postgres .venv/bin/python -m pytest -q tests/integration
.venv/bin/ruff check .
.venv/bin/mypy
scripts/relock.sh                                  # пересобрать lock-файлы с хешами после правки requirements*.txt (нужен uv)
```

Интеграционные тесты создают одноразовую схему на каждый тест и удаляют её, поэтому им можно дать базу, в которой лежат другие данные. CI (`.github/workflows/ci.yml`) запускает ruff, mypy, все тесты на PostgreSQL 18 с порогом покрытия 80 % и `pip-audit`. См. [CONTRIBUTING.md](CONTRIBUTING.md).

## Безопасность и ответственное использование

- **Файл сессии Telethon даёт полный доступ к аккаунту Telegram.** Он добавлен в `.gitignore`; не кладите его в резервные копии, которыми делитесь, и никогда не публикуйте. Если файл утёк, завершите сессию: Telegram → Настройки → Устройства.
- Используйте собственные `API_ID`/`API_HASH` и соблюдайте [условия использования API Telegram](https://core.telegram.org/api/terms). Автоматизация пользовательского аккаунта несёт риск ограничений или блокировки; бот ограничивает частоту запросов, но ответственность за использование на вас.
- Уважайте права авторов читаемых каналов. Stenabot оставляет ссылку на каждый оригинал и рассчитан на личную ленту, а не на массовую републикацию чужого контента.
- О найденных уязвимостях сообщайте, как описано в [SECURITY.md](SECURITY.md).
